📦 区块头结构 (80 Bytes)

比特币区块头是区块的"元数据"，固定80字节。就像信封上的信息，告诉你这个区块的基本情况。

💡 提示：点击下面的字段查看详细解释！
Version 4 bytes 0x20000000 区块版本号
PrevHash 32 bytes 000000000000000000... 前一个区块哈希
Merkle Root 32 bytes 4a5e1e4baab89f3a... 交易默克尔根
Timestamp 4 bytes 1231006505 时间戳 (Unix)
Bits 4 bytes 0x1d00ffff 难度目标 (压缩)
Nonce 4 bytes 2083236893 随机数

📝 Version - 区块版本号

Version 是一个 4 字节的整数，用于标识这个区块遵循的规则版本。

例如：0x20000000 表示使用 BIP34、BIP66 和 BIP65 规则

在代码中：你需要读取 4 个字节，并按小端序解析为整数。

# Python 示例 import struct version_bytes = raw_bytes[0:4] # 取出前4字节 version = struct.unpack(', version_bytes)[0] # 小端序解包

🔄 字节序 (Endianness)

字节序是指多字节数据在内存中的存储顺序。比特币主要使用小端序 (Little-Endian)

🔵 大端序 (Big-Endian) - 人类阅读习惯

高位字节在前，低位字节在后。就像我们平时写数字：123

🟠 小端序 (Little-Endian) - 比特币使用

低位字节在前，高位字节在后。x86 处理器使用这种方式。

0x78
低位
0x56
0x34
0x12
高位

数值：0x12345678 (305419896) - 值相同，只是存储顺序不同！

⚠️ 重要：比特币区块头中的 Version、Timestamp、Bits、Nonce 都是小端序存储。
但 PrevHash 和 MerkleRoot 作为哈希值，显示时通常用大端序（方便人类阅读）！
# Python 字节序转换示例 import struct # 小端序编码 (比特币存储格式) value = 0x12345678 little_endian = struct.pack(', value) # b'\x78\x56\x34\x12' # 大端序编码 (人类阅读格式) big_endian = struct.pack('>I', value) # b'\x12\x34\x56\x78' # 翻转字节序 flipped = little_endian[::-1] # 字节翻转

🔐 SHA256 哈希算法

比特币使用 双 SHA256：对数据计算两次 SHA256 哈希。

💡 为什么用双 SHA256？
1. 增加安全性，防止长度扩展攻击
2. 这是中本聪的设计选择，已成为比特币的标准
import hashlib def double_sha256(data): """比特币标准的双 SHA256 哈希""" first_hash = hashlib.sha256(data).digest() second_hash = hashlib.sha256(first_hash).digest() return second_hash # 计算区块哈希 (区块头 80 字节) block_header = bytes.fromhex("0100000081cd02...") block_hash = double_sha256(block_header) print("区块哈希:", block_hash[::-1].hex()) # 翻转后显示

🔍 哈希特性

🎲 确定性

相同输入必定产生相同输出

❄️ 雪崩效应

输入微小变化导致输出完全不同

🔒 不可逆

无法从哈希值反推原始数据

⚡ 固定长度

无论输入多长，输出都是 256 位

⛰️ 难度目标 (Difficulty Target)

比特币通过"难度目标"控制出块速度（约10分钟/块）。目标值越小，挖矿难度越大。

目标值范围
0 2²⁵⁶-1
🎯 规则：区块哈希（作为大整数）必须 小于 目标值才算有效！

目标值越小 → 有效范围越小 → 越难找到符合条件的 Nonce
# Bits 和目标值的转换 def bits_to_target(bits): """ bits: 4 字节，压缩格式的难度 格式: [系数: 3 字节][指数: 1 字节] 目标值 = 系数 * 256^(指数-3) """ exponent = bits[-1] # 最后一个字节是指数 coefficient = int.from_bytes(bits[:3], 'little') target = coefficient * (256 ** (exponent - 3)) return target # 创世区块的 Bits: 0x1d00ffff # 系数: 0x00ffff, 指数: 0x1d (29) # 目标值 = 0x00ffff * 256^(29-3) = 0x00000000ffff0000...
💡 记忆技巧：
Bits 的压缩格式是为了节省空间。在区块头中只有 4 字节，但实际目标值可能是 32 字节！

🌳 默克尔根 (Merkle Root)

默克尔根是所有交易的哈希指纹，存储在区块头中。

作用：

  • 验证交易是否属于某个区块
  • 轻节点只需下载区块头即可验证交易
  • 任何交易修改都会改变默克尔根

📝 计算过程：
1. 每笔交易计算哈希
2. 两两配对，再次哈希
3. 重复直到只剩一个哈希 → 默克尔根
def calculate_merkle_root(tx_hashes): """简化版默克尔根计算""" if len(tx_hashes) == 0: return bytes(32) while len(tx_hashes) > 1: if len(tx_hashes) % 2 == 1: tx_hashes.append(tx_hashes[-1]) # 奇数复制最后一个 new_level = [] for i in range(0, len(tx_hashes), 2): combined = tx_hashes[i] + tx_hashes[i+1] new_level.append(double_sha256(combined)) tx_hashes = new_level return tx_hashes[0]
