🔄 字节序 (Endianness)

理解大端序与小端序的区别，掌握比特币数据解析中的字节序转换

📖 概念对比

🔴 大端序 (Big-Endian)

高位字节存储在低地址（人类阅读习惯）

0x12 高位
0x34
0x56
0x78 低位
↑ 内存地址增加方向

数值：0x12345678 = 305419896

🔵 小端序 (Little-Endian)

低位字节存储在低地址（x86 处理器使用）

0x78 低位
0x56
0x34
0x12 高位
↑ 内存地址增加方向

数值：0x12345678 = 305419896

💡 比特币中的字节序：
• Version、Timestamp、Bits、Nonce 使用小端序存储
• PrevHash、MerkleRoot 存储时是小端序，但显示时通常转为大端序（方便人类阅读）

注意：比特币区块头中的哈希值（PrevHash、MerkleRoot）在存储时是小端序， 但在区块浏览器中显示时是大端序。这就是为什么你看到的区块哈希和原始字节数据看起来"相反"。

💻 代码示例

Python

import struct # 大端序编码 (>) 和小端序编码 (<) value = 0x12345678 # 转换为 4 字节 big_endian = struct.pack('>I', value) # b'\x12\x34\x56\x78' little_endian = struct.pack(', value) # b'\x78\x56\x34\x12' # 翻转字节序 flipped = little_endian[::-1] # b'\x12\x34\x56\x78' # 解析字节 parsed = struct.unpack(', little_endian)[0] # 305419896

JavaScript

// 创建 ArrayBuffer const buffer = new ArrayBuffer(4); const view = new DataView(buffer); // 小端序写入 view.setUint32(0, 0x12345678, true); // true = little-endian // 大端序写入 view.setUint32(0, 0x12345678, false); // false = big-endian // 翻转字节序 const flipEndian = (bytes) => bytes.reverse();
